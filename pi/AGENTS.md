# pi/ — agent notes

Config for [Pi](https://www.npmjs.com/package/@earendil-works/pi-coding-agent).
Only what is easy to get wrong here; general conventions are in the repo
root's `AGENTS.md` and `STYLE.md`.

## A new extension needs a `links.toml` entry

Pi loads extensions from `~/.pi/agent/extensions/`, so a file added under
`pi/extensions/` with no matching `[[link]]` block is never installed. It
looks finished in git and does nothing on the machine. Add the entry in the
same commit as the extension.

`test/test_pi_extension_links.py` fails the suite if you forget, and it has
already caught this class once: `custom-footer.ts` was hand-symlinked from
the worktree it was written in, so when that worktree was removed the
installed link dangled and the extension silently stopped loading.

## This is the only TypeScript tree in the repo

`pi/package.json` drives four stages, all run by
`test/test_pi_ts_checks.py` via `bun run <stage>`:

| Stage | Command |
|---|---|
| `test` | `bun test` (specs live in `pi/test/`) |
| `typecheck` | `tsc --noEmit` |
| `lint` | `oxlint extensions test` |
| `format:check` | `prettier --check extensions test` |

Run them from `pi/`, not the repo root. A fresh worktree has no
`pi/node_modules`, and all four stages **skip** rather than fail when it is
missing — run `bun install` in `pi/` first, or you will read a green suite
that checked nothing.

**Both checks are scoped to `extensions` and `test`, not to `pi/` itself.**
That is why this file and its `CLAUDE.md` symlink sit at `pi/` root:
prettier formats markdown by default, so moving them into `pi/extensions/`
or `pi/test/` would start failing `format:check`. Leave them where they are.

## Generated files, not authored

- `pi/prompts/second-opinion.md` and `pi/skills/second-opinion/SKILL.md` are
  generated by `claude/scripts/gen_second_opinion.py` from
  `templates/second_opinion.md.tmpl` plus a per-harness parameter table — two
  of seven such copies across the harness directories. Edit the template
  (shared wording) or the script's parameter table (pi-specific wording), then
  regenerate. Hand-edits are overwritten.
- `pi/skills/{dashboard,grill-me,backlog-item,make-skill,spec,standup,to-tickets}/SKILL.md`
  are generated by `claude/scripts/gen_skills.py` from
  `templates/{dashboard,grill_me,backlog_item,make_skill,spec,standup,to_tickets}.md.tmpl`
  plus `gen_skills.py`'s `CAPABILITY_TABLE`/`gen_skills_params.py` tables.
  `dashboard`/`grill-me`/`backlog-item`/`make-skill` are also generated for
  `claude`/`copilot`/`opencode`/`agy`; `spec`/`standup`/`to-tickets` are
  generated only for `claude`/`opencode`/`pi` (see `gen_skills.py`'s
  `SKILL_HARNESSES` and root `AGENTS.md`'s "Harness maintenance tiers"
  section — copilot/agy are best-effort and don't get new generated
  skills). Edit the template or the params tables, then regenerate.
  Hand-edits are overwritten.
- `pi/settings.json` is a copy-once seed. Its `skills` array lists
  `pi/skills` (all 8 generated skills above) **and** `agy/skills`, listed
  second, purely as a legacy fallback — Pi's own docs (`docs/skills.md`)
  document that a name collision across skill directories "warns and keeps
  the first skill found," so `pi/skills` always wins and `agy/skills` has
  no effect on any skill name `pi/skills` already covers.
